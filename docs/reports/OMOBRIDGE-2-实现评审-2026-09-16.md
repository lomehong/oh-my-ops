## 三、缺口清单（可执行）

- **G1（验证·必修）T7b 假绿窗口**：夹具 `scripts/probe-yuyi-reply-frame.mjs` 场景 C 的 5s 观察窗短于插件最坏重连时延。改法：观察窗提至 ≥10s，或改为「先断言未修复件必然重连（长窗）→ 修复件不重连」双段判据；并在 `执行记录 §3.2` 标注红基线为窗口敏感值（15s：3/8 确定；5s：偶发 4/7）。
- **G2（验证·必修）失败路径无用例**：`:1619-1620`（`sendFailureReply` 回信帧）与 `:2689`（重试后失败日志）零覆盖。改法：夹具加「首投拒绝 → 重试 → 失败」场景，断言第二帧 `from.device`/`to` 形态与失败日志。
- **G3（不确定性·必修）对端 device 为空的回信地址**：`to={device:"",target:sessionID}`（对端未升级上游 0.1.0，`from.device` 空；或对端无 `sessionID` 时回落到 `origMsg.from.name` 裸别名）在真机的可解析性未知，桩无法判定。改法：登记「未知/待真机复验」，并入真机 E2E 判据清单。
- **G4（影响面·必修）补影响面与回滚节**：① `vendor/yuyi-omp-extension.js` 是上游构建拷贝（历史 `chore(vendor): 同步…` 为整文件替换）→ 本次修复若不上游化，**下一次 vendor 同步会静默回退**（应登记为维护风险，而非仅「上游分发」）；② 4009「replaced」真机触发源（同 token 多会话 / 初始化双连接）与实例 `closed=true` 后的恢复路径（仅靠再次 `connect()` 新建实例，运行期无自动恢复）；③ 回滚步骤（`/tmp/deployed-backup-yuyi-omp.js` 备份 + `git revert` + 重跑 `scripts/install.sh` 部署 `vendor/…`）。
- **G5（证据·建议）外部基准未取到可验证证据**：`docs/hub-plugin` §3.3.3/§3.5.1/§3.6 与上游 `/dist/omp.js` 0.1.0 本机不可得；桩裁决为手写复刻。按 `architect-knowledge/practice/review-baseline-discipline.md` 第 1/2 条，需在记录中显式标注基准来源与不可回源项（现仅由生产报错原文间接佐证）。
