## 三、本轮残留发现（落定前小修 3 项，均为文档级）

1. **【重要-低】§1「已拍板前提」表残留旧文**：#3（L61）未含「本机管理 token 强制」（§6 #3/§9 管理面入口行已更新）；#6（L64）仍写「自签 + 证书公钥 pin（`curl --pinnedpubkey`）；禁止 `-k`」——**正是被实测否定的 pin-only 旧表述**，与 REQ-I05/§6 #7/AC-I09 的「cacert+pin 双锚」矛盾。实施者速查该表会重蹈 N1。修法：#6 同步为「自签 CA + SPKI pin 双锚」；#3 补 admin token。
2. **【建议】§0 五问 Q5（L29）计数过时**：仍写「4 项 owner 决策已拍板（TLS pin / …）」，实际已 6 项且 TLS 表述已变（§10 L542 为「6 项…（4 项追认 + TLS 路径 + 目标平台）」）。
3. **【建议】script.sha256 校验顺序不一致**：§7.4.1 L279 与 §7.4.4 L363 要求「下载脚本后先校验（对 manifest 内哈希）再执行」，但示例命令（L346-348）是「取 script → 直接 `sh`」，且 manifest 在脚本内部才获取——顺序上无法在执行前完成 manifest 哈希校验。修法：示例改为先取 manifest 再取 script 校验后执行，或明确 script 响应自带哈希的校验方式。

**另登记一项实现期注意（不阻断）**：el7 legacy 路径的 openssl SPKI pin 校验与 curl 下载是**两次连接**（TOCTOU 窗口），最终信任锚是 `--cacert` 交付链、pin 为连续性辅助校验——语义上弱于现代路径，建议在 §7.4.3 legacy 分支注明，并依赖已登记的 el7 真机探针验证 openssl 1.0.2 命令序列可用性。
