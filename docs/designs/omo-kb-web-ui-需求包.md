# 结构化需求包：kb 服务 Web 配置前端（一期）

- 来源：主人 2026-09-21 口头需求「升级改造 kb 服务，增加前端页面，可以在前端页面完成必要的配置」
- 决策门已清：scope=面板+签码+配置修改（主人选 b）；认证=yufu 负责、一期预留接口（主人拍板）；暴露=同端口 8787（主人拍板）

## 可验收目标

1. 服务机浏览器访问 `https://<服务机>:8787/ui` 可完成：查看服务状态/登记表/审计、签发 enroll 码（绑定设备名+TTL，明文只显示一次）、查看并修改服务配置（写回 config.env，预检通过后自动重启生效）——全程无需 SSH 编辑文件。
2. 实例侧 `/enroll`、`/healthz` 行为与现状完全一致（回归全绿）。
3. 认证鉴权由 yufu 负责（服务部署在 yufu 之后，UI 平面 TLS 由 yufu 终结）：`/ui` 全平面要求 yufu 注入的身份头（键名可配，默认 `X-Forwarded-User`），缺失 ⇒ 401；`OMO_KB_UI` 默认 off（升级即安全态，对接 yufu 后显式开启）。

## 范围（做）

- 服务端新增 `/ui` 路由组：登录会话（一期占位）、状态/登记表/审计只读 API、签码 API、配置读写 API、配置预检+重启。
- 零依赖单页前端（服务包内 `ui/index.html`，vanilla JS，中文），无构建链、无新 npm 依赖。
- 配置写回：白名单键校验 → 原子写（0600 + .bak 一代）→ `--check` 预检（独立端口起服务自证）→ 停旧起新。
- 每个写操作入审计日志（actor=`ui`）。
- 发布：服务包加 `ui/` 与清单断言；`test:ci` 保持全绿。

## 不做项（显式排除）

- bot 生命周期 UI 操作（rotate/revoke/删号、fleet 逐台签码）——主人明确选 b 不选 c。
- yufu 认证的实际实现（二期；接口本期预留）。
- 多用户/角色权限分级。
- TLS 证书签发/更换 UI（证书文件路径可配，签发仍走 install.sh）。
- enroll 兑换协议任何变更（实例侧零改动）。
- 前端框架/构建链（React/Vite 等）。

- el7 无 systemd，服务由 nohup 管理（依据 install-enroll-service.sh:402）⇒ 重启采用停旧起新由服务进程自理。
